# 卡牌拖拽与速度倾斜

## 效果与原理

鼠标提供目标位置，位置弹簧让卡牌中心带着轻微滞后追踪目标；卡牌的横向速度生成目标倾角，旋转弹簧再让角度平滑变化。停住时速度衰减，卡牌回正；松手后可以回到初始位置，也可以停在释放位置。

按下时保存一次鼠标到中心的固定偏移。这个偏移不随卡牌旋转，因此在相同初始状态下，点击中心、边缘和角落，只要鼠标位移轨迹相同，卡牌就具有相同的位置与倾斜响应。

本篇按当前 003 的实现整理。它使用二维 Transform 运动、正交相机与阻尼弹簧；参数是本实验的交互选择，不代表确认了小丑牌原作的 CPU 更新公式。

| 层面 | 计算内容 |
| --- | --- |
| Geometry | CPU 更新整个 Quad 的位置与 Z 轴旋转，网格顶点本身不变 |
| Pixel | 普通 Unlit 卡面采样，保留纹理透明度 |
| Driver | 输入捕获、固定偏移、位置弹簧、速度到倾角的映射、旋转弹簧与释放状态 |
| Pass | 阴影和卡面分别绘制，Alpha 混合，不写深度 |

## 所需资源

| 资源 | 职责 |

## 输入与中间变量

| 变量 | 类型、空间或单位 | 用途 |
| --- | --- | --- |
| screen | float2，屏幕像素、左下原点 | 输入系统给出的指针位置 |
| m、mPrev | float2，世界空间 XY | 当前与上一帧指针位置 |
| p、v | float2，世界单位、世界单位/秒 | 实际卡牌中心与位置弹簧速度，跨帧保存 |
| pTarget | float2，世界空间 XY | 位置弹簧的目标中心 |
| o | float2，世界空间偏移 | 按下时的 m-p，一次拖拽中固定 |
| home、releaseTarget | float2，世界空间 XY | 初始锚点与本次释放后的目标位置 |
| theta、u | float，度、度/秒 | 相对初始姿态的倾角与角速度，跨帧保存 |
| thetaTarget | float，度 | 从横向速度生成的目标倾角 |
| H | float，世界单位 | 未旋转卡牌的高度，用于速度归一化 |
| thetaMax | float，度 | 最大允许倾角 |
| sMax | float，卡牌高度/秒 | 达到最大目标倾角需要的横向速度 |
| wFollow、wHome | float，每秒 | 按住跟随与松手回位的位置响应频率 |
| wTilt、wStraight | float，每秒 | 增大或反向倾斜、向零回正的旋转响应频率 |
| zeta | float，无单位 | 旋转阻尼比，当前范围 0.4–1 |
| dt、h | float，秒 | 帧时间与运动子步时间 |
| state | Idle / Dragging / Settling | 稳定、已抓取、已释放但仍恢复中 |

H 是卡片本身的世界高度，不是旋转后屏幕包围盒的高度。当前单位 Quad 没有父节点，因此取 `abs(card.lossyScale.y)`；换成其他尺寸的网格时，还要乘上网格的局部高度。

## 算法流程

### 1. 初始化姿态并把鼠标换算到卡牌平面

记录初始中心 home、初始 Z 坐标和初始 Z 轴角度。令 p=home、v=0、theta=0、u=0，状态为 Idle。

对每次输入，用相机的 `ScreenPointToRay(screen)` 生成射线，与卡片所在的 XY 平面求交，得到世界位置 m。鼠标与相机投影必须使用同一套屏幕坐标。

按下时，将 m 通过卡片的 `InverseTransformPoint` 转到局部空间。若局部 X/Y 都在 -0.5 到 0.5 内，则命中。这一步使用当前 Transform，所以卡片已经旋转时仍能命中。

**输出**：世界指针位置与命中结果。命中检查只决定是否开始抓取，不参与后续倾角计算。

### 2. 按下时记录固定偏移并捕获输入

命中后记录：

$$
o=m_0-p_0
$$

其中 m0、p0 是按下瞬间的指针位置与中心。随后令 mPrev=m0、pTarget=p0，切换为 Dragging，再同步触发 `dragStarted`。保持当前 p、v、theta、u，不因再次抓取而清零惯性或跳变姿态。

拖动期间的目标中心为：

$$
pTarget=m-o=p_0+(m-m_0)
$$

目标中心只取决于鼠标相对按下位置的位移。抓取位置被常量 o 抵消，相同相对轨迹会得到相同目标中心。

不要每帧把 o 随旋转一起转动。那样会让倾斜改变位置目标，再通过位置速度改变倾斜，手感就会依赖点击位置。固定偏移意味着倾斜时最初点中的纹理点可以相对鼠标移动；卡牌始终绕自身中心旋转。

**输出**：固定偏移与已捕获状态。指针离开卡片或经过调参面板后仍继续拖拽，直到释放或失焦；不能每帧重新要求指针命中卡片。

### 3. 处理释放并划分运动子步

松手时先结束输入捕获，切换为 Settling，再触发 `dragEnded`。重复释放不重复发送事件。

| 释放模式 | releaseTarget | 位置速度 |
| --- | --- | --- |
| 回到初始位置 | home | 保留当前 v，允许释放后短暂延续运动 |
| 停在释放中心 | 当前 p | 清零 v，保持中心，只恢复角度 |

两种模式都令目标倾角为 0，但保留当前角度和角速度，随后平滑回正。失焦或禁用组件也结束捕获，避免错过释放后一直停在 Dragging。

每帧使用未缩放时间间隔，最多接受 0.1 秒，并拆成不超过约 1/120 秒的子步：

$$
dt'=\min(dt,0.1),\qquad n=\max(1,\lceil120dt'\rceil),\qquad h=dt'/n
$$

第 i 个子步的指针取 `lerp(mPrev,m,i/n)`。这只是对两个已采集输入做插值，不会恢复帧间没有采集到的急转弯。超过 0.1 秒的卡顿时间不补算；源码还在向上取整前减去很小的容差，避免浮点误差多拆一个子步。

**输出**：每个子步的时间、指针位置和当前状态。以下旋转与位置计算在每个子步内依次执行。

### 4. 从横向速度生成目标倾角

拖动时先使用进入本子步前保存的位置弹簧速度 v，计算：

$$
s=\frac{v_x}{\max(H,0.01)}
$$

$$
thetaTarget=-thetaMax\cdot\operatorname{clamp}\left(\frac{s}{\max(sMax,0.1)},-1,1\right)
$$

相机朝 +Z，正的 Z 轴角度在画面中逆时针旋转；负号让向右移动时顺时针倾斜，向左移动时反向。纯竖向拖动不会主动产生倾角。

thetaMax 和 sMax 分别控制角度上限与达到上限所需的速度。例如 thetaMax=60°、sMax=6 时，卡片横向速度为 1、3、6 个卡高/秒，目标倾角大小分别为 10°、30°、60°。

sMax 是饱和速度，不是开始倾斜的开关。调高 sMax 会减小同一速度下的倾角；thetaMax 保持较大，就能得到“缓慢移动轻微倾斜，猛烈拖动才出现大角度”的效果。

**输出**：thetaTarget。已经释放时直接取 0，不再用回位速度驱动倾斜。

### 5. 选择倾斜或回正响应，更新角度

满足下列任一条件时使用 wStraight，否则使用 wTilt：

- 目标角度接近零，当前代码为 `abs(thetaTarget) < 0.001`。
- 目标角度与当前角度同号，且目标的绝对值更小。

这让增大倾斜或反向使用 Tilt response，收回倾斜使用 Straighten speed。按住鼠标但停止移动时，同样可以进入回正响应；不必等到松手。

用阻尼弹簧更新 theta 和 u，再将实际角度限制在 ±thetaMax 内。默认 zeta=1；取更低值允许过冲和回弹。响应频率控制快慢，阻尼比控制是否振荡，两者职责不同。

**输出**：平滑后的倾角。目标曾经达到最大倾角，不代表短促甩动时实际角度一定能追到上限。

### 6. 用位置弹簧追踪目标中心

若正在拖动，pTarget=本子步指针-o，使用 wFollow；若正在恢复，pTarget=releaseTarget，使用 wHome。对位置 X、Y 分量分别执行临界阻尼更新。

位置与旋转共用以下弹簧模型：

$$
\ddot x+2\zeta\omega\dot x+\omega^2(x-x^*)=0
$$

x 是当前位置或角度，x* 是对应目标，v 是该量的速度，omega 是响应频率。位置始终使用 zeta=1；旋转允许调整阻尼。omega 不是最大移动速度，也不是动画时长。

在一个子步内把目标视为常量。临界阻尼时，令 $y=x-x^*$、$j=v+\omega y$，精确更新为：

$$
x_{new}=x^*+(y+jh)e^{-\omega h}
$$

$$
v_{new}=(v-\omega jh)e^{-\omega h}
$$

两个式子都使用更新前的 y、j、v。不能先覆盖速度再计算位置。保留速度状态才能产生运动连续性；它与每帧直接把位置设成鼠标坐标不同。

**输出**：新位置与速度。新速度供下一个子步生成目标倾角，旋转结果不反向修改位置目标。

### 7. 判断恢复完成并写入显示姿态

在 Settling 中，当位置、速度、角度、角速度都接近目标时，吸附到精确目标、清零速度并切换为 Idle。当前实现使用以下阈值：位置距离小于 0.001 世界单位、速度小于 0.01 世界单位/秒、倾角小于 0.02°、角速度小于 0.1°/秒。

每帧所有子步结束后，令 mPrev=m，将 p 写入卡片中心，将“初始 Z 轴角度 + theta”写入旋转。阴影复制卡片旋转和缩放，位置取卡片位置加固定世界偏移。

卡面使用普通对象到裁剪空间变换与纹理采样。阴影和卡面都使用 `Blend SrcAlpha OneMinusSrcAlpha`、`ZWrite Off`、`Cull Off`，通过排序让阴影位于卡面后面。

**输出**：整张卡片及阴影的最终姿态。CENTER、TARGET、HOME 分别是实际中心、目标中心和初始锚点的调试标记。

## 整体伪代码

下面给出默认临界阻尼版本。`criticalSpring` 返回位置与速度两个值，位置参数可逐分量计算；可选的低阻尼分支见后面的公式。

```text
初始化：
    p = home = 初始卡片中心
    v = 0；theta = 0；u = 0
    releaseTarget = pTarget = home
    state = Idle

有效按下（未捕获、命中卡片、没有点在面板上）：
    o = m - p
    mPrev = m
    pTarget = p
    state = Dragging
    触发 dragStarted；不修改 p、v、theta、u

释放、失焦或禁用（仅当 state == Dragging）：
    releaseTarget = 回家模式 ? home : p
    如果停在释放位置：v = 0
    pTarget = releaseTarget；thetaTarget = 0
    state = Settling
    触发 dragEnded

criticalSpring(x, v, target, omega, h)：
    y = x - target
    j = v + omega * y
    e = exp(-omega * h)
    返回 (target + (y+j*h)*e, (v-omega*j*h)*e)

每帧（Driver，先处理输入事件）：
    如果 dt <= 0：返回
    dt = min(dt, 0.1)
    n = max(1, ceil(dt * 120))
    h = dt / n
    对 i = 1 到 n：
        如果 state == Idle：退出子步循环
        dragging = state == Dragging
        s = v.x / max(H, 0.01)
        thetaTarget = dragging ? -thetaMax*clamp(s/max(sMax,0.1),-1,1) : 0
        straightening = abs(thetaTarget) < 0.001
                        或 (thetaTarget*theta > 0 且 abs(thetaTarget) < abs(theta))
        w = straightening ? wStraight : wTilt
        (theta, u) = criticalSpring(theta, u, thetaTarget, w, h)
        theta = clamp(theta, -thetaMax, thetaMax)

        pTarget = dragging ? lerp(mPrev,m,i/n)-o : releaseTarget
        w = dragging ? wFollow : wHome
        (p, v) = criticalSpring(p, v, pTarget, w, h)

        如果正在 Settling 且位置、速度、角度、角速度均接近目标：
            p = releaseTarget；v = 0；theta = 0；u = 0
            state = Idle

    mPrev = m
    更新卡片 Transform 与阴影

每个顶点（Geometry）：
    按 Transform 正常变换顶点，传递 uv

每个片元（Pixel）：
    输出 纹理采样(uv) * 材质颜色

绘制（Pass）：
    先画偏移阴影，再画卡面；使用透明混合
```

### 可选的低阻尼旋转

当 $0<\zeta<1$ 时，令 $\omega_d=\omega\sqrt{1-\zeta^2}$、$e=e^{-\zeta\omega h}$、$c=\cos(\omega_dh)$、$s=\sin(\omega_dh)$，弹簧更新替换为：

$$
x_{new}=x^*+e\left[yc+\frac{v+\zeta\omega y}{\omega_d}s\right]
$$

$$
v_{new}=e\left[vc-\frac{\zeta\omega v+\omega^2y}{\omega_d}s\right]
$$

这里的 s 是正弦中间量，与速度归一化步骤中的 s 无关。当前代码把 zeta 限制在 0.4–1，接近 1 时使用临界阻尼分支，避免分母趋近零。默认不需要启用低阻尼；后续悬停与拖拽切换的回弹来源仍需单独确认。

## 参数与手感的对应

| 面板参数 | Controller 字段 | 当前默认值 | 调大后的作用 |
| --- | --- | --- | --- |
| Follow speed (held) | positionResponse | 55 | 更快追上 TARGET，位置滞后更小 |
| Return home speed (released) | returnResponse | 30 | 松手后更快回到 HOME |
| Maximum tilt | maxTilt | 60° | 允许更大的目标与实际倾角 |
| Speed for max tilt | speedForMaxTilt | 6 卡高/秒 | 同一速度下倾角变小，更难达到最大倾角 |
| Tilt response | rotationResponse | 40 | 更快进入新的倾斜方向和幅度 |
| Straighten speed | straightenResponse | 65 | 停住或松手后更快收回倾角 |
| Rotation damping | rotationDamping | 1 | 在当前范围内，越接近 1 越能抑制振荡 |

位置追不上鼠标时调整 Follow speed；位置已经跟上但角度迟迟不正时调整 Straighten speed。按住停顿后的目标倾角依赖位置速度衰减，因此位置跟随很慢时，只加快回正仍然会感觉拖沓。

调大 Maximum tilt 而保持 Speed for max tilt 不变，会同时增大未饱和速度下的倾角。若希望保留低速倾斜比例，同时把最大角度从 60° 提到 80°，可以把饱和速度从 6 同比提到 8 卡高/秒；若想让低速倾斜更弱，则进一步提高饱和速度。

## 窗口尺寸与鼠标速度

对于当前正交相机，设 orthographicSize 为 O，相机视口的屏幕像素高度为 Sh，保持正常宽高比和固定 O。可见世界高度为 2O，屏幕像素位移与目标世界位移的关系为：

$$
\Delta p=\frac{2O}{Sh}\Delta screen
$$

两轴都使用相同的每像素世界尺度。003 的 O=3.6，可见高度为 7.2 世界单位：

| 视口高度 | 鼠标移动 100 像素对应的目标位移 |
| --- | --- |
| 720 像素 | 1 世界单位 |
| 360 像素 | 2 世界单位 |

因此窗口等比例缩小后，相同像素速度会生成更高的目标世界速度，卡片也更容易达到大倾角。若在相同时间内移动相同窗口比例，目标世界轨迹则相同，弹簧响应基本一致。

卡高为 H 时，鼠标速度换成卡高/秒的比例为 $2O/(ShH)$。这描述输入尺度；位置弹簧的瞬时速度仍可能与鼠标速度不同，不能直接把像素阈值当作实际倾角触发条件。

这里讨论的是相机视口在输入坐标中的尺寸。只降低内部渲染分辨率、但保持窗口与输入映射不变，不等于缩小窗口。只改变窗口宽度而不改变高度时，固定 O 的每像素世界尺度也不会按宽度比例改变。鼠标物理移动距离还受 DPI 和系统指针设置影响。

以上是当前坐标换算的推导，不是本次新增的跨分辨率运行测试。用户观察到的小丑牌小窗口更灵敏，与该机制相符，但不足以确认原作采用同一套速度公式。

## 实现约束

- 当前相机朝 +Z，卡片在固定 XY 平面上，独立放置且只绕 Z 轴旋转；父节点缩放、透视相机和多相机视口需要重新检查坐标约定。
- 输入捕获与几何命中分开。拖动中离开卡面不释放，失焦或按键抬起才结束捕获。
- 位置和旋转状态跨帧保存；只插值位置而丢弃速度，无法复现这里的响应。
- 拖动期间缩放卡牌或改变相机投影会改变换算关系；当前固定偏移不自动补偿这些变化。
- dt 子步减少帧率差异，不保证任意采样率、任意指针轨迹严格相同。
- 只让一个控制器写卡片姿态，每帧只调用一次 Step。关闭 Demo 的 readMouseInput 不会停止它调用 Step。
- 同一材质可用于卡面与阴影的独立实例；阴影采用固定世界偏移，不是光照系统计算出的投影。
- 后续接入 001 时，`dragStarted` 可用于当帧关闭 hover 权重；仅禁用悬停脚本不一定会清掉已写入的 Shader 参数。恢复 hover 可按释放事件或 IsSettled 决定，目前尚未整合。
