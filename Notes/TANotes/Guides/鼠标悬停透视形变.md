# 鼠标悬停透视形变

## 效果与原理

根据鼠标到平面各顶点的距离，分别修改顶点的裁剪空间 w。GPU 随后执行透视除法，让四个角产生不同的屏幕位移，卡面由此呈现倾斜感。

$$
(x_{ndc},y_{ndc})=(x_{clip}/w,y_{clip}/w)
$$

保持裁剪坐标 xy 不变、w 为正时，减小 w 会让顶点远离视口中心。例如 x 为 0.4，w 从 1 变为 0.8，投影后的 x 就从 0.4 变为 0.5。

本篇采用正交相机、轴对齐四顶点平面，按现有 001 的公式描述实现。它产生屏幕上的透视感，缩放中心是视口中心。

## 输入与中间变量

| 变量 | 类型、空间或单位 | 用途 |
| --- | --- | --- |
| P | float3，对象空间 | 原始顶点位置 |
| uv | float2，局部纹理坐标 | 卡面采样位置 |
| m | float2，视口像素，左下原点 | 鼠标位置 |
| S | float2，像素 | 视口宽高，均大于 0 |
| s | float，像素 | 鼠标距离归一化尺度 |
| h | float，0–1 | 当前悬停量，跨帧保存 |
| hTarget | float，0 或 1 | 是否悬停的目标状态 |
| r | float，每秒 | 悬停过渡速度，取正数 |
| k | float，无单位 | 形变强度，当前材质范围 0–3 |
| dt | float，秒 | 当前帧时间间隔 |
| C | float4，裁剪空间 | 原始顶点投影坐标 |
| p | float2，视口像素，左下原点 | 未形变顶点的屏幕位置 |
| d | float，无单位 | 顶点到视口中心的归一化距离 |
| o | float2，无单位 | 顶点相对鼠标的归一化偏移 |
| deltaW | float，裁剪坐标 w 的增量 | 本顶点的形变量 |

Unity 参数对应：m → `_MousePixels`，S → `_ViewportSize`，s → `_ScreenScale`，h → `_Hover`，k → `_Strength`。

## 算法流程

### 1. 每帧整理输入并更新悬停量

将鼠标屏幕像素坐标减去相机视口的左下角偏移，得到 m。将未形变卡片投影为视口矩形，鼠标在矩形内时令 hTarget=1，否则为 0。

用指数过渡更新 h：

$$
h\leftarrow\operatorname{lerp}(h,hTarget,1-e^{-r\,dt})
$$

取卡片未形变屏幕高度的 0.8 倍作为 s。把 m、S、s、h、k 通过 MaterialPropertyBlock 传入 Shader。

**输出**：这一帧所有顶点共用的输入参数。命中检测使用未形变矩形，避免形变边界反过来影响悬停状态。

### 2. 将每个顶点转换到视口像素坐标

先得到未形变的裁剪坐标 C，再计算用于距离判断的位置 p：

```hlsl
float4 C = TransformObjectToHClip(P);
float2 ndc = C.xy / C.w;
ndc.y *= _ProjectionParams.x;
float2 p = (ndc * 0.5 + 0.5) * S;
```

Y 方向修正用于对齐 Unity 投影与左下原点的鼠标坐标。这里手动除以 w 只是计算 p；最终顶点输出仍然是四维裁剪坐标。

**输出**：原始 C 与像素位置 p。

### 3. 计算顶点相对视口中心和鼠标的距离

$$
d=\frac{\lVert p-S/2\rVert}{\lVert S\rVert},\qquad
o=\frac{p-m}{\max(s,1)}
$$

d 用于调制不同屏幕位置的形变强度；o 用于计算顶点与鼠标的距离平方。除以 s 后，距离不再直接使用像素量级。

**输出**：d 和 $o\cdot o$。

### 4. 把距离映射为 w 的增量

$$
\Delta w=k\cdot0.2[-0.03-0.3\max(0,0.3-d)]
\cdot h\cdot\frac{o\cdot o}{\max(2-d,0.1)}
$$

$$
C'_w=\max(C_w+\Delta w,0.2),\qquad C'_{xyz}=C_{xyz}
$$

当前公式通常得到负的增量。鼠标距离平方越大，w 减少的幅度越大；视口中心距离 d 会进一步调制这个幅度。h 或 k 为 0 时形变量为 0。w 下限用于避免透视除法的分母接近零。

其中的数值系数是当前案例的风格选择。可复用结构是“距离 → 形变量 → 修改 w”，其他视觉风格可以替换距离映射函数。

**输出**：交给 GPU 的裁剪坐标 C'，以及顶点 UV。

### 5. 插值纹理并输出卡面颜色

GPU 根据 C' 完成透视除法、三角形光栅化和透视正确 UV 插值。片元 Shader 使用插值后的 UV 采样卡面 RGBA。

材质使用 `Blend SrcAlpha OneMinusSrcAlpha`、`ZWrite Off`、`Cull Off`，将卡面按透明度混合到背景。

**输出**：具有透视形变的卡面。

## 整体伪代码

```text
每帧（Driver）：
    m = 鼠标屏幕像素坐标 - 相机视口左下角
    S = 相机视口宽高
    rect = 未形变卡片投影到视口后的矩形
    hTarget = m 在 rect 内 ? 1 : 0
    h = lerp(h, hTarget, 1 - exp(-r * dt))
    s = rect.height * 0.8
    上传 m、S、h、s、k

每个顶点（Geometry）：
    C = 对象空间转裁剪空间(P)
    ndc = C.xy / C.w
    ndc.y *= Unity 投影 Y 修正符号
    p = (ndc * 0.5 + 0.5) * S
    d = length(p - S * 0.5) / length(S)
    o = (p - m) / max(s, 1)
    deltaW = k * 0.2 * (-0.03 - 0.3 * max(0, 0.3-d))
             * h * dot(o, o) / max(2-d, 0.1)
    C.w = max(C.w + deltaW, 0.2)
    输出 C 与 uv

GPU：
    透视除法、光栅化、透视正确插值

每个片元（Pixel）：
    rgba = 采样卡面纹理(插值后的 uv)
    输出 rgba

绘制（Pass）：
    一个透明 Unlit Pass，使用 Alpha 混合，不写深度
```

## 实现约束

- m 与 p 必须使用相同视口、原点和像素单位；p 从未形变顶点计算。
- 当前 CPU 矩形命中方案适用于轴对齐卡片与正交相机。
- 只修改 w 会围绕视口中心缩放，卡片偏离中心时会产生位置漂移。
- 网格包围盒需要覆盖形变范围，否则可能提前被 CPU 剔除。
- Shader Graph 的 Vertex Position 接收三维对象空间位置，需要额外反算与 UV 插值修正，不能直接填入 C'。
