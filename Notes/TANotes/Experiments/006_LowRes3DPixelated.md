# 006 · Low-res 3D Pixelated

研究问题：内部分辨率和放大采样方式，如何改变实时 3D 模型的轮廓、细小结构和运动表现？

状态：Minimal 已完成并验证。属于 [[3D像素风格与程序动画实验路线]] 的第一个实验。只验证低分辨率渲染，不声称匹配 A Short Hike、ULTRAKILL 或视频作者的完整实现。

场景：`Assets/_Lab/Experiments/006_LowRes3DPixelated/Scenes/006_LowRes3D_Minimal.unity`。菜单：`TechArtLab > 006 > Create or Open Minimal`。打开后进入 Play；独立于 001–005，不引用卡牌实验资源。

## Geometry、Pixel、Driver、Pass

| 层面 | 当前实现 |
| --- | --- |
| Geometry | Unity 基础模型与通过 AssetDatabase 保存的楔形 Mesh；运行时不把模型体素化 |
| Pixel | 可读 HLSL 的连续 Lambert 光照、固定环境底色和主方向光阴影；没有 Toon 色阶、高光和像素纹理 |
| Driver | Input System 键鼠输入、固定等距视角、自由轨道旋转与固定时间驱动的慢速平移 |
| Pass | 主场景相机直接绘制到低分辨率 RT；空背景相机清屏；Overlay Canvas 的 RawImage 放大 RT；IMGUI 面板保持屏幕分辨率 |

低分辨率来自相机目标纹理，不是先渲染一张完整分辨率的场景图再做马赛克。阴影仍由当前 URP 的阴影流程生成，其成本和分辨率不能按主画面 RT 的像素比例推算。

## 分辨率与采样

目标宽高固定为 16:9，提供 160×90、320×180、480×270、640×360。纹理使用 ARGB32、24 位深度、Clamp，关闭 mipmap 与 MSAA；相机关闭后处理、AA、HDR 和动态分辨率。验证环境使用现有 PC 管线，Render Scale 为 1，没有修改项目的质量设置或 Renderer。

设源图尺寸为 $(W,H)$，可用显示区域为 $(A_w,A_h)$。能放大时选择整数倍：

$$
s=\left\lfloor\min\left(\frac{A_w}{W},\frac{A_h}{H}\right)\right\rfloor.
$$

图像显示为 $(sW,sH)$，居中且起点对齐到整屏像素，剩余空间留边。Point 在源图中选择最近的纹素，不混合相邻颜色；整数放大后，每个源纹素占据同色的 $s\times s$ 区域。Bilinear 按采样位置混合邻近纹素，原像素块边界出现过渡色。

当区域小于源图时，退回保持比例的缩小显示，面板显示 fractional fit 提示；此时不保证像素块等宽。建议扩大 Game 视图观察。

切换分辨率时，整数倍留边可能使画面的实际显示尺寸改变。例如 960 像素宽区域中，640 宽的源图只能按 1 倍显示，而 320 宽的源图可按 3 倍显示。因此视觉比较应读取面板的 Target、Display、Scale；自动截图统一输出到 1920×1080，避免把显示面积变化误认为采样差异。

Native reference 根据可用区域选择能容纳的最大 16:9 整数尺寸，按 1:1 显示；这里的 native 指结果区域，不是整个窗口。它保留相同几何、光照、相机和关闭 AA 的条件，只提高目标尺寸。

## 相机与光照公式

固定视角采用正交投影，yaw 为 45°、pitch 为约 35.26439°，正交半高 $S=4.1$。此条件下，相机平面上的每个源像素覆盖：

$$
\Delta=\frac{2S}{H}.
$$

320×180 时约为 0.04556 世界单位／像素；640×360 时减半。细杆的实际屏幕宽度还取决于方向与投影，不能只把世界截面宽度除以 $\Delta$ 就视为所有角度下的精确覆盖。

测试平移为世界 X 方向 $x(t)=0.65\sin(0.65t)$，相机位置与观察目标一起偏移，朝向不变。当前没有像素对齐或输出补偿；后续 007 用它作为未稳定化的对照。自由旋转和透视模式也保留连续投影。

Shader 中 $N$ 是归一化世界空间法线，$L$ 指向主光源，$A$ 为固定环境底色强度，$C_b$ 为材质颜色，$C_l$ 为光色及强度，$a$ 为距离与阴影衰减：

$$
C=C_b\left[A+(1-A)\max(N\cdot L,0)C_l a\right].
$$

此环境项是复现选择，不是实际环境光照积分。保持连续明暗是为了把光照分段与采样分开研究。Shader 使用 ForwardOnly 和自有主方向光 ShadowCaster；两个 Pass 的 UnityPerMaterial 布局一致。当前只针对场景中的主方向光，不实现额外点光源、GI 或复杂材质。

## 操作

| 操作 | 行为 |
| --- | --- |
| 1–4 | 四档低分辨率；退出 native 对照 |
| N | 切换 Native reference |
| B | Point／Bilinear |
| O | 正交／透视 |
| F 或 R | 恢复固定等距视角与距离，停止平移；不重置分辨率和滤波 |
| 右键拖动结果区域 | 自由旋转；停止平移回放 |
| 在结果区域滚轮 | 正交模式改变正交半高，透视模式改变相机距离 |
| T | 启停慢速平移，每次从时间零开始 |
| Space | 暂停／继续平移回放；不冻结整个应用 |
| H | 隐藏／显示面板和文字，保留相同结果区域 |

建议先固定相机，以 2+B 比较滤波；再以 1–4 比较细杆和球轮廓；最后用 T 比较运动时的像素变化。面板也提供对应按钮。后台运行仅在本组件启用期间打开，禁用时恢复原状态；失焦时不读取键鼠。

## 验证与证据

2026-10-03，Unity 6000.6.0f1、URP 17.6.0、Direct3D11、Linear、现有 PC 管线。通过 Unity CLI 导入、编译、创建场景与运行 `TechArtLab > 006 > Validate and Capture`。初始未连接是因为 Unity 未启动；打开现有版本后 CLI 正常工作，没有升级依赖。

本地证据目录：`References/006_LowRes3DPixelated/analysis/unity/`。`validation.txt` 保存实际报告。图像包括 `source_90/180/270/360.png`、`point_90/180/270/360.png`、`point_compare.png`、`bilinear_compare.png`、`pan_0/1.png`、`perspective.png`、`orbit_105.png`、`native_reference.png` 和 `controls.png`。

**Verified（Unity）**：

- 自动连续帧与显式相机渲染对照，单通道 1/255 容差下有差异的像素数为 0；切换目标尺寸、滤波与相机后，自动帧仍保留各材质颜色。
- 四档源图统一放大至 1920×1080，Point 的 12×12、6×6、4×4、3×3 像素块全部保持均匀颜色。
- 320×180 放大至 1280×720，Point 与 Bilinear 有 49,100 个像素超过单通道 1/255 差异阈值；Bilinear 在对应 4×4 区域中有 62,693 个像素与该区域首像素不一致，确认边界混色。
- 固定平移 $t=0$ 与 $t=1$ 有 6,717 个像素变化，重复 $t=0$ 在相同容差下完全一致。这证明回放可重复，不代表运动已稳定化。
- 透视及 yaw=105° 的相机输出与固定视角不同且包含场景物体；Native 输出 1:1。布局计算覆盖 960×592、1600×900 和 200×100 可用区域，保持比例、不溢出，并区分整数放大与不足尺寸的缩小。
- 最终编译无错误；运行验证后的 Console 无错误、无警告。此前出现的材质颜色异常与 Play 切换后的面板贴图警告已修复，并通过复跑检查。

**Observation（Unity）**：最终截图已视觉检查；球和斜坡轮廓有清楚阶梯，Bilinear 边缘更柔，四根不同粗细的杆在不同采样下覆盖不同。自动统计的蓝色像素数为 61、268、667、1,071，随源图尺寸变化；这一总数不单独证明某根细杆何时完全消失。

**Inference**：降低 RT 尺寸有望减少主场景像素着色成本，但顶点、提交、阴影和最终合成成本不会等比减少。本次没有 GPU/CPU 性能基准，不报告 FPS 提升。
