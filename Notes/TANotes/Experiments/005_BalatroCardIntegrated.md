# 005 · Balatro Card Integrated

研究问题：如何用一个输入与状态控制器组合悬停、拖拽、延迟溶解和边缘粒子，并在松手时明确区分取消与继续消失？

场景：`Assets/_Lab/Experiments/005_BalatroCardIntegrated/Scenes/005_CardIntegrated_Minimal.unity`。菜单：`TechArtLab > 005 > Create or Open Minimal`。复用 [[001_BalatroCardHover]] 的公式、[[003_BalatroCardDrag]] 的运动控制器、[[004_BalatroDissolveParticles]] 的运行组件，保留原独立场景。

## 组合方式

| 层面 | 实现 |
| --- | --- |
| Geometry | 003 写卡牌 Transform，组合 Shader 顶点阶段应用 001 的 clip-w 形变 |
| Pixel | 004 的共享场纹理生成溶解遮罩与边缘颜色 |
| Driver | 单一协调器管理抓取、计时、释放、悬停恢复和固定时钟 |
| Pass | 固定偏移阴影、卡面和世界空间方片粒子分别透明绘制 |

`IntegratedCardDemo` 是唯一输入来源，`IntegratedCardController` 推进状态和时钟；不挂旧的 Hover、Dissolve 或 Drag Demo。003 只负责运动，004 统一写入卡面、阴影的 MaterialPropertyBlock，防止多个组件覆盖属性。

005 的 Shader 与 004 共用 `DissolveCardPass.hlsl`，只在 005 编译时启用悬停顶点分支。悬停用未形变卡面命中；鼠标退出时夹住输入位置再淡出，避免远处鼠标放大残余形变。拖拽、回位和溶解期间 hover 为零。

## 状态与时间规则

| 状态 | 转换与行为 |
| --- | --- |
| Ready | 卡牌完整、运动稳定，可以悬停或按下 |
| Dragging | 按下当帧关闭 hover；中心未越阈值时不计时 |
| Countdown | 实际中心离锚点超过卡高的 3% 后锁定计时，拖回原位也不中断 |
| Returning | 溶解前松手立即清零计时，003 返回锚点，稳定后回到 Ready |
| Dissolving | 计时达到 1 秒，开始 1.2 秒退出；按住时继续拖动，松手后中心停留、角度回正 |
| Hidden | 卡牌完全消失，不接受再次抓取，粒子自然结束；R 才恢复 |

距离使用实际显示中心与最初锚点的世界距离，以卡高归一化；不使用鼠标目标点，所以抓取边角不改变阈值。松手先于计时更新处理：截止时刻同一更新收到松手，也以取消为先。

失焦按松手处理，已经开始的溶解不中断。正在回位时允许重新抓取，新计时从零开始。按住停在原地或仅移动阈值内不会触发；进入 Countdown 后不会因为回到阈值内而取消。

时钟使用未缩放时间，按 1/60 秒推进；每步先更新拖拽，再判断离位和计时，再更新溶解与粒子。003 内部继续使用原来的运动子步。长帧最多接受 0.1 秒，自动回放与实时输入使用同一状态链。

## 操作与接口

按住卡片稍微拖离原位，继续按住便会溶解。溶解前松手取消，溶解中松手留在释放位置消失。

- `R`：恢复完整卡牌，回到锚点，清除粒子、捕获和倒计时。
- `T`：固定轨迹演示按住拖离直到溶解。
- Space：暂停或继续；暂停时仍处理松手释放捕获。
- 面板：离位距离、延迟、溶解时长、位置跟随、回正、最大倾角、饱和速度、随机图案与粒子开关。

交互接口为 `Press(world)`、`Move(world)`、`Release()`、`Advance(dt)`、`ResetCard()`。输入坐标为卡片平面世界 XY。`PointerActive` 决定能否触发悬停，Demo 将其与应用焦点同步；自动验证可显式设置。

005 引用 004 的纹理、粒子材质、运行组件和共享 HLSL，也引用 003 的网格和控制器；它是可独立打开的场景，不是脱离这些实验目录的独立资源包。

## 验证记录

2026-10-01，Unity 6000.6.0f1、URP 17.6.0、DX11、Linear。通过 CLI 执行 `TechArtLab > 005 > Validate and Capture`。报告和悬停、倒计时、按住溶解、释放溶解、隐藏、复位截图保存在本地 `References/005_BalatroCardIntegrated/analysis/unity/`。

**Verified（Unity）**：完整卡面、中心悬停下，与 001 Shader 在相同材质输入条件下逐像素一致。自动输入检查覆盖当帧关闭 hover、稳定后恢复、静止按下、小于阈值、离位后拖回、释放清零、重新抓取、失焦、截止时刻松手优先，以及溶解中释放保持中心、隐藏不可命中、尾部粒子结束和复位。

固定相对轨迹下，在 30/60/120 FPS 和中心、右上角、左下角三种抓取位置，均在输入开始后约 1.066667 秒观察到溶解触发；这是移动越阈值所需时间与延迟之和，不是将延迟改成了 1.066667 秒。共同半秒采样点的位置与角度组合差异最大约 0.000003。

相机目标视口高度 360/720/1080、固定 16:9 比例下，相同视口相对位移映射到相同世界位移，并能触发同一交互链。这验证的是投影与输入换算，没有自动操作系统窗口大小或测量鼠标物理移动距离。

最终两个场景的编译、运行检查无新增错误或警告，面板和代表状态截图已检查。没有为此次文档声称验证原游戏 CPU 驱动。

## 四角悬停的深度裁剪修正

**Observation（Unity）**：鼠标靠近卡牌四角时，卡面出现大片黑色三角区域。固定右上角输入后，只把相机远裁剪距离从 1000 改为 100，缺失区域便恢复；修复前截图保存在本地 `References/005_BalatroCardIntegrated/analysis/unity/corners/`。

**Verified（Unity）**：组合顶点公式只修改了裁剪空间的 `w`，因此除了预期的 `x/w`、`y/w` 形变，还改变了 `z/w` 深度。005 的相机裁剪范围为 0.3–1000，在当前 DX11 reversed-Z 投影下，四角悬停能使部分顶点越过近裁剪面。黑色来自卡面被裁掉后露出的阴影。001 的相机范围为 0.1–100，原来的中心悬停对照没有覆盖这一条件。

**Unity Reproduction Choice**：005 把 hover 作为屏幕投影形变，保留原顶点深度。设原裁剪坐标为 $(x,y,z,w)$、形变后为 $w'$，同时令 $z'=z\,w'/w$，使 $z'/w'=z/w$。这样保留原有屏幕轮廓和透视 UV 插值，又不会因为形变而跨越深度裁剪边界。修正位于共享 HLSL 的 `CARD_HOVER` 分支，004 不启用该分支。

修复后通过 Unity CLI 重跑 005 验证：四角输入各检查强度 1 和 3，阴影开启，以远裁剪距离 50 下未被裁剪的 001 为画面参考，与远裁剪距离 1000 下的组合版比较；8 组均无超过单通道 1/255 容差的像素差异。四角代表截图为 `hover_corner_*.png`。中心悬停、拖拽、取消回位、延迟溶解与 30/60/120 FPS 检查同样通过。
