# 008 · Lo-fi Low-poly

研究问题：几何细分、法线和材质配色分别怎样影响低模风格？低分辨率采样又会叠加什么变化？

2026-10-04，Minimal 已实现并通过 Unity 验证。属于 [[3D像素风格与程序动画实验路线]] 的第三项。默认使用结果区域的原生分辨率，先观察模型与光照，再切低分辨率；采样原理接续 [[006_LowRes3DPixelated]]，不叠加 [[007_PixelStable3D]] 的相机稳定化。

场景：`Assets/_Lab/Experiments/008_LoFiLowPoly/Scenes/008_LoFiLowPoly_Minimal.unity`。Unity 菜单：`TechArtLab > 008 > Create or Open Minimal`，进入 Play。自动验证入口：`TechArtLab > 008 > Validate and Capture`。

## 场景与变量

场景是一块小型林地：两棵树各含树干和三簇树冠，三块岩石、七块路面石板、三级台阶，以及草面和土层。物体摆放、岩石形变和初始光照固定，便于逐项比较。

| 变量 | 可选项 | 保持不变的部分 |
| --- | --- | --- |
| 几何细分 | 树冠／岩石单网格 20、80、320 个三角形；树干 6、12、24 段 | 场景位置、材质角色、相机和光照 |
| 法线 | Flat、Smooth | 对应等级下每个三角形的三个顶点位置 |
| 色板 | 4、6、8 种材质底色 | 几何、法线、光照；不是后处理色阶量化 |
| 输出 | Native、640×360、320×180、160×90 | 相机投影和世界构图；整数放大时显示面积可能改变 |
| 灯光 | 方位角、高度角，关闭／硬／软阴影 | 模型与配色 |
| 诊断 | Beauty、Albedo、Normals、Silhouette | 场景与相机；只改变片元输出 |

默认值为最低细分、Flat、8 色、Native、硬阴影。地面、石板和台阶始终使用硬边立方体网格；Flat／Smooth 切换只作用于树冠、岩石和树干。固定对象承担构图及参照作用，不把整个场景的所有硬边都强行平滑。

## Geometry、Pixel、Driver、Pass

| 层面 | 实现 |
| --- | --- |
| Geometry | 编辑器生成树冠、岩石和树干的 18 个 Mesh 资源；运行时只切换已有网格 |
| Pixel | 可读 HLSL 的连续 Lambert 明暗、环境底色、主方向光阴影；另有三个诊断分支 |
| Driver | 控制细分、法线、底色映射、光方向和输出尺寸；右键轨道观察与滚轮缩放 |
| Pass | 一台场景相机直接写入 RT；空背景相机清屏；Overlay RawImage 显示结果，IMGUI 绘制面板 |

`LoFiMeshes` 负责生成和拆分网格，`LoFiExperiment` 通过 Unity 保存 Mesh、材质和独立场景，`LoFiDemo` 管理运行参数，`Validate008` 检查几何与图像结果。008 的运行资源全部保存在自己的实验目录，没有依赖 006/007 的场景、材质或脚本，也没有修改全局 Renderer、质量设置或包版本。

## 几何细分与轮廓

树冠从单位二十面体开始。每次把三角形的三条边分别取中点，并把中点归一化投影回单位球面，再把原三角形拆成四个三角形。因此第 $n$ 级的面数为：

$$
F_n=20\cdot4^n.
$$

通过边索引缓存让相邻三角形复用同一个中点，不生成重叠但不相连的顶点。共享网格的顶点数为 12、42、162；半径重投影使细分后的表面更接近圆球，所以细分确实会改变轮廓。只在原平面上细分、而不改变顶点位置，并不能产生同样的轮廓改善。

岩石复用这套拓扑。对单位方向 $v$，先计算固定的半径扰动：

$$
\rho(v)=1+0.12\sin(3v_x+1.2v_z)+0.08v_yv_z,
$$

再用 $\operatorname{diag}(1.1,0.7,0.9)\,\rho(v)v$ 形成压扁且不规则的岩石。各等级使用同一形变函数，没有每次切换时重新随机，因此看到的差异主要来自采样密度。

树干使用顶部较细的截锥，上下盖与侧面分离顶点，使 Smooth 时仍保留盖面折角。每段包含两个侧面三角形及两个盖面三角形，总数为 $4m$，对应 24、48、96 个三角形。

## Flat 与 Smooth

Flat 为每个三角形复制三份独立顶点，三点的法线都取面法线。局部空间顶点为 $a,b,c$ 时：

$$
n_f=\frac{(b-a)\times(c-a)}{\|(b-a)\times(c-a)\|}.
$$

Smooth 保留共享顶点，并调用 Unity 的 `RecalculateNormals` 生成顶点法线。Shader 把法线转换到世界空间，在片元阶段对插值结果重新归一化。这样同一三角形内部也可产生渐变明暗，但顶点位置和遮挡轮廓不变。

本实验的 Flat 与 Smooth 从同一份索引三角形序列生成，不分别建模。三档轮廓图逐像素一致，是“只改法线”的实际证据；不能仅凭看起来相似就认定几何相同。

| 全场景细分等级 | 三角形数 | Flat 顶点数 | Smooth 顶点数 |
| --- | ---: | ---: | ---: |
| 0 | 372 | 972 | 448 |
| 1 | 960 | 2,736 | 766 |
| 2 | 3,216 | 9,504 | 1,942 |

以上按场景实例累加，包含固定的地面、石板和台阶；不包含阴影 Pass 的重复绘制，也不是唯一 Mesh 资源的存储总量。Flat 的三角形数没有增加，但拆分顶点增加了顶点数据量；不能把低模风格直接等同于最低顶点成本。

## 底色色板与连续光照

八个材质角色分别是土层、草面、树干、三种树冠颜色、岩石、路面。4 色映射合并土层与树干、三种树冠、岩石与路面；6 色保留独立树干和两种树冠颜色；8 色让各角色独立。

所有物体使用同一个材质，通过 `MaterialPropertyBlock` 设置底色和诊断模式。底色由明确的角色表选择，没有对最终屏幕颜色做最近色映射或逐通道截断。

设世界空间单位法线为 $N$，指向主光源的单位向量为 $L$，底色为 $C_b$，光色与强度为 $C_l$，环境底色系数为 $A=0.32$，光衰减与阴影乘积为 $a$：

$$
C=C_b\left[A+(1-A)\max(N\cdot L,0)C_l a\right].
$$

即使只用 4 种底色，光照仍可生成更多颜色。Albedo 绕过光照，用于检查底色；Normals 输出世界法线的 $0.5N+0.5$；Silhouette 把可见表面统一输出为白色。后两者也是诊断图，不代表最终美术效果。

**Verified（本地管线与 Unity）**：当前 PC Renderer 使用 Forward+。初版缺少 `_CLUSTER_LIGHT_LOOP` 变体时，008 在当前逐物体参数路径下只显示环境底色，Flat／Smooth 光照对照失败。本地 URP 17.6 的 `ShaderLibrary/RealtimeLights.hlsl` 表明 `GetMainLight` 的衰减数据路径取决于该变体。补齐变体声明后，主光照、法线对照及阴影验证通过。没有通过改动全局管线绕过问题。

## 分辨率、光照与操作

Native 根据结果区域选择能容纳的最大 16:9 整数尺寸，保持 1:1 显示。其余三档使用 Point 和整数倍放大，不足一倍时保持比例缩小并显示提示。全部关闭 MSAA、相机 AA、HDR、后处理与 mipmap，避免这些变量干扰对照。

固定方向光以方位角和高度角控制。Hard 与 Soft 使用当前 URP 阴影实现；软阴影不等于真实面积光源，效果还受管线阴影分辨率、过滤和级联配置影响。本次保留项目设置，只切换灯光的阴影模式。

| 操作 | 行为 |
| --- | --- |
| 1 / 2 / 3 | 三档几何细分 |
| N | 切换 Flat／Smooth |
| P | 循环 4／6／8 色底色映射 |
| V | 循环 Beauty／Albedo／Normals／Silhouette |
| L | 循环关闭／硬／软阴影 |
| 输出按钮 | Native 或三档低分辨率 |
| 光照滑条 | 调节光方向 |
| 结果区域右键拖动、滚轮 | 相机旋转、缩放 |
| R | 恢复全部基准参数，包括相机、光照和输出 |
| H | 隐藏或显示界面，结果区域不变 |

建议先关阴影、保持 Native 和最低细分，用 N 比较同一轮廓下的明暗；再以轮廓视图比较 1 与 3；回到 Albedo 比较色板，最后才切低分辨率和阴影。阴影开启时，改变法线也可能影响法线偏移带来的阴影边缘，因此法线隔离验证关闭阴影。

## 验证与证据

2026-10-04，Unity 6000.6.0f1、URP 17.6.0、Direct3D11、Linear、现有 PC Forward+ 管线，通过 Unity CLI 创建、导入、编译和验证。原始报告与截图位于 `References/008_LoFiLowPoly/analysis/unity/`。

**Verified（Unity，`validation.txt`）**：

- 18 个网格检查通过：Flat／Smooth 的对应三角形顶点位置一致，Flat 三点法线均等于面法线，Smooth 法线为单位向量，没有退化三角形。细分三角形数与公式一致。
- 640×360、固定相机、阴影关闭时，三档 Flat／Smooth 轮廓图差异均为 0；Beauty 差异像素数为 13,256、13,592、10,164。图像差异采用 RGB 单通道 1/255 容差。
- 最低与最高细分的轮廓图有 1,163 个像素变化，确认细分实际改变了轮廓。
- Albedo 中排除背景后恰有 4、6、8 种颜色；对应 Flat Beauty 图有 41、45、51 种颜色，确认色板没有量化最终光照颜色。
- 关闭与硬阴影有 6,342 个像素差异，硬与软阴影有 4,221 个差异；光方位角从 -35° 改为 65° 有 37,627 个像素变化。
- 160×90、320×180、640×360 统一放大到 1280×720，分别保持均匀的 8×8、4×4、2×2 同色块。
- 当前 Native 结果为 1904×1071，显示比例 1:1；自动连续帧与显式渲染有 0 个超容差差异像素。此尺寸取决于当前 Game 视图可用区域。
- 布局计算覆盖常规大小和小于源图的显示区域；组件禁用／启用后 RT 正确释放与重建，退出／重入 Play 没有新增错误或警告，见 `lifecycle.txt`。

代表图包括 `level_0/1/2_flat.png`、`level_0/1/2_smooth.png`、对应 `silhouette` 图，`palette_4/6/8_albedo.png`、对应 `beauty` 图，`shadow_off/hard/soft.png`、`light_65.png`、`normal_view.png`、`source_90/180/360.png`、`point_90/180/360.png` 和 `native_frame.png`。`controls_native.png` 与 `controls_low.png` 保留操作界面。

**Observation（Unity）**：原生分辨率界面和 Smooth 对照已视觉检查；Flat 树冠与岩石呈现清楚的三角面明暗，Smooth 保留多边形外轮廓而内部明暗更连续。修复后的面板完整显示参数、网格统计及操作提示。

## 性能与风格边界

**Inference**：减少三角形可降低部分几何处理成本，但本场景网格很小，实际瓶颈不一定在顶点。Flat 的复制顶点、阴影重复绘制、逐物体参数及最终合成仍有成本。本次没有 CPU/GPU 性能基准，不报告 FPS 改善。

色板在这里是美术组织约束，不会自动减少 Draw Call，也没有使用索引纹理压缩显存。网格在编辑器生成并保存，运行时切换引用，不每帧重新细分；更新材质属性仅在相关参数改变时执行。低分辨率可以减少主画面像素数量，但不等比减少阴影、几何和提交成本。

Sokpop、Ilequ 在路线中提供风格方向；本次缺少对应具体作品、片段及原始工程证据，未确认它们的实际实现。这里是用于拆分变量的 Unity Reproduction Choice，没有完成原作匹配。没有 Toon 分段、高光、纹理细节、描边、风吹树动画或相机像素稳定化。进一步美术打磨应保留此独立 Minimal 场景。
