# 003 · Balatro Card Drag

研究问题：鼠标的目标位置如何驱动二维卡片的位置、倾斜与释放回位，让跟随滞后和旋转惯性可以分开观察？

按输入、计算和输出顺序阅读实现，见 [[卡牌拖拽与速度倾斜]]；本篇保留案例的参数、交互接口与验证记录。

独立场景为 `Assets/_Lab/Experiments/003_BalatroCardDrag/Scenes/003_CardDrag_Minimal.unity`。卡牌保持完整，使用自制锁卡测试图。[[001_BalatroCardHover]] 的悬停形变、[[002_BalatroCardDissolve]] 的溶解和粒子尚未接入。

## 机制与实现范围

| 层面 | 实现 |
| --- | --- |
| Geometry | 四顶点 Quad；CPU 更新位置与 Z 轴旋转，不修改顶点或裁剪空间 w |
| Pixel | 普通 Unlit 贴图采样；阴影使用黑色、0.3 alpha 的相同卡片轮廓 |
| Driver | 输入采样、固定抓取偏移、位置临界阻尼、速度驱动倾斜、旋转阻尼、释放回位 |
| Pass | 阴影与卡面分别绘制，透明混合，关闭深度写入，通过排序保证卡面在前 |

三个源文件分别负责：`CardDragController.cs` 保存交互状态和运动状态；`CardDragDemo.cs` 读取鼠标、绘制调参面板与固定轨迹回放；`CardDrag.shader` 显示卡面。`CardDragExperiment.cs` 创建资源并执行验证。

运行场景只引用 003 内的资源。测试贴图通过 Unity 从 002 的自制锁卡复制，003 不依赖 002 的运行脚本或材质。

## 参考观察与判断边界

**Observation**：`drag.mp4` 前段缓慢移动时倾斜较小，中段快速折返时倾斜增大，末段约 9.7–10.1 秒卡片返回中央并回正。录像没有鼠标按键状态，无法精确定位释放帧。

参考分析和采样图保留在 `References/002_BalatroDragDissolveParticles/analysis/` 的 `followup_2026-09-19.md`、`drag_sheet.jpg` 和 `drag_return.jpg`。

**Inference**：位置平滑、速度驱动倾斜和释放回位能够解释这些表现，但不能由录像推导出唯一运动公式。用户观察到的按下时悬停消退及轻微回弹仍待后续组合实验验证。

**Unity Reproduction Choice**：本实验使用阻尼弹簧近似，默认旋转阻尼比为 1。降低阻尼比可以观察过冲和回弹，这是实验选项，不代表确认原作如此实现。当前没有从原作抓帧确认 CPU 拖拽更新代码。

## 坐标、命中与抓取点

当前约定是朝 +Z 的正交相机、独立放置且只绕 Z 轴旋转的卡面。鼠标像素位置通过相机射线与卡片所在 XY 平面求交，得到世界位置。命中检测把这个位置变换到卡片局部坐标，检查 X、Y 是否都在 -0.5 到 0.5 内，所以旋转后的卡片仍可命中。

按下时记录指针与卡片中心的世界空间偏移 $o=m_0-p_0$，不修改当前卡片姿态；拖动时目标中心为：

$$
p^*=m-o=p_0+(m-m_0)
$$

$m$ 是当前指针世界位置，$m_0$、$p_0$ 是按下瞬间的指针位置和卡片中心。偏移在本次拖拽中保持不变，不随卡片旋转。相同初始姿态、速度和鼠标位移下，点击中心、边缘或角落都会得到相同的目标中心轨迹，因此位置、倾角与回正响应一致。卡牌统一绕自身中心旋转，运动中实际中心仍有阻尼滞后。

**Unity Reproduction Choice**：优先满足不同点击位置手感一致、按下不跳位的交互要求。卡面倾斜时，最初点击的纹理点可以相对鼠标移动；不会通过额外平移让该纹理点始终贴住鼠标。回位途中重新抓取也重新记录固定世界偏移，保留当前姿态和速度。

旧版每步计算 $p^*=m-R(\theta)Sg$，让局部抓取点随旋转变动。这会形成“倾角改变目标中心 → 中心速度改变 → 倾角再次改变”的反馈，反馈大小与抓取点有关。2026-09-20 根据用户反馈移除了该耦合；它是本次 Unity 实现问题，不代表原游戏行为。

鼠标移出卡片或经过控制面板时仍保留捕获，释放后才结束拖动。点击面板不会开始抓牌。失焦或禁用组件会结束捕获，避免卡片永久停留在拖动态。

## 位置与旋转响应

位置由临界阻尼弹簧追踪目标：

$$
\ddot x+2\omega\dot x+\omega^2(x-x^*)=0
$$

对于一个子步内不变的目标，令 $y=x-x^*$、$j=v+\omega y$，更新为：

$$
x_{new}=x^*+(y+j\Delta t)e^{-\omega\Delta t}
$$

$$
v_{new}=(v-\omega j\Delta t)e^{-\omega\Delta t}
$$

`positionResponse`（面板 `Follow speed (held)`）为拖动时的 $\omega$，`returnResponse`（`Return home speed (released)`）为释放后的 $\omega$，单位为每秒。数值越大，跟随或回位越快。回位保留释放瞬间速度，快速释放后可能继续运动一小段，不会立即把速度归零。移动整个 Transform 会带动整张卡片；CENTER 和 TARGET 是实际中心与目标中心的标记，并非只有中心点在运动。

倾斜目标使用实际显示卡片的横向速度，而不是直接使用鼠标位置：

$$
\theta^*=-\theta_{max}\operatorname{clamp}\left(\frac{v_x/H}{s_{max}},-1,1\right)
$$

$H$ 是世界空间卡高，$s_{max}$ 是 `Speed for max tilt`，单位为卡牌高度/秒（H/s），$\theta_{max}$ 是 `Maximum tilt`。增大 $s_{max}$ 会让同一速度下的倾斜变小，需要更快横移才能达到最大目标倾角。它是饱和速度，不是开始倾斜的硬阈值。输入使用位置弹簧的横向速度，不能把鼠标速度直接当作卡片速度。

例如最大角度 60°、饱和速度 6 H/s 时，卡片横向速度为 1、3、6 H/s，目标倾角大小分别为 10°、30°、60°。旋转还要经过平滑，因此短促甩动未必能让实际角度到达上限。向右移动产生顺时针倾斜，向左反向；停住后实际速度衰减，目标倾斜随之回到 0。

旧版使用 `Tilt strength`（$k$）作为角度/速度比例，对应关系是 $s_{max}=\theta_{max}/k$。旧预设的 35° 与强度 18 对应约 1.94 H/s；新预设为 60° 与 6 H/s，允许更大的倾角，但需要更高速度才能达到。

旋转弹簧现在有两个响应速度：`Tilt response` 控制倾斜增大或反向；`Straighten speed` 控制目标角度向零收拢，包括保持按住但停止移动和松手后。具体选择条件为目标接近零，或目标与当前角度同号且绝对值更小。切换响应时保留角速度，不直接跳角。按住停顿时，位置速度也需要先衰减，所以快速恢复通常需要同时提高 `Follow speed` 和 `Straighten speed`。

`Rotation damping` 为旋转阻尼比，范围 0.4–1。默认 1 为临界阻尼，低于 1 允许过冲；实际角度限制在 `Maximum tilt` 内。释放后目标倾斜立即变为 0，实际角度逐渐回正。

每帧拆成不超过约 1/120 秒的子步，在子步间线性插值两帧指针采样。单次步长最多接受 0.1 秒，长时间卡顿后不补算全部缺失时间。该方法减少帧率差异，但不是任意轨迹、任意采样率下的严格数学等价。

## 交互状态与后续组合接口

| 状态 | 含义 |
| --- | --- |
| Idle | 已稳定，可以开始抓取 |
| Dragging | 已捕获指针，正在追踪拖拽目标 |
| Settling | 已释放，位置和角度正在恢复 |

`TryBeginDrag(world)` 成功时先改变状态，再同步调用 `dragStarted`；外部不必等下一帧才能知道按下。重复按下不会重复发事件。`EndDrag()` 先退出拖动态再调用 `dragEnded`，重复释放不会重复发事件。

组合时可以：

1. 在 `dragStarted` 中关闭 001 的 hover 权重，并将拖拽姿态交给 003。
2. 在 `dragEnded` 后根据需要立即恢复 hover，或者等待 `IsSettled` 为 true 再恢复。
3. 由统一输入调用 `TryBeginDrag`、`MovePointer`、`EndDrag`；关闭 Demo 的 `readMouseInput` 后，Demo 仍可调用 `Step`。若完全禁用 Demo，则组合控制器负责每帧调用 `Step(dt)`，不要重复更新。

`IsDragging` 在按下成功的当帧就为 true；`IsSettled` 则区分“已释放”和“回正完成”。UnityEvent 可通过 Inspector 绑定，也可通过代码订阅。

单纯禁用 001 的脚本不一定能清掉已经写入的 Shader 参数。后续适配器应明确把 hover 权重写为 0，并决定是否保留其缓动状态。这次没有修改 001，也没有把按下时的视觉回弹提前当成正确答案。

当前 Controller 独占卡片 Transform。组合时应明确父子层级和姿态所有权，避免多个脚本同时写相同 Transform；也要重新验证顶点形变后的视觉轮廓与命中区域。

## 场景操作

打开 `TechArtLab > 003 > Create or Open Minimal`，进入 Play 后在 Game 视图按住卡牌拖动。

| 操作 | 作用 |
| --- | --- |
| 鼠标左键按住卡片 | 抓取并拖动，松开释放 |
| Return home on release | 开启时回到初始锚点；关闭时保持释放中心，只恢复角度 |
| `R` / Reset | 回到初始位置和角度 |
| `T` / Replay | 播放慢移、快速折返、停住、释放的固定轨迹 |
| Space | 暂停或继续固定轨迹回放 |
| Show target and center markers | 显示初始锚点、目标中心和实际中心 |
| Follow speed / Return home speed | 分别调整按住时的位置跟随、释放后的回位速度 |
| Maximum tilt / Speed for max tilt | 调整角度上限、达到最大目标倾角所需的横向卡片速度 |
| Tilt response / Straighten speed | 分别调整倾斜增大或反向的响应、向零回正的响应 |
| Rotation damping | 调整旋转阻尼；低于 1 的回弹为实验选项 |
| Original tuning / Fast / high-speed tilt | 切换旧参数或快速跟随、高速大倾角参数 |

固定轨迹使用当前参数，改变参数后按 T 重播，能够直接比较响应差异。默认回放共 5 秒，在 3 秒释放。原地停留模式下再次抓取、回位途中再次抓取均允许。

当前场景默认参数：

| 参数 | 默认值 | 调大后的效果 |
| --- | --- | --- |
| Follow speed (held) | 55 | 整张卡片更快追上 TARGET，拖动更贴手 |
| Return home speed (released) | 30 | 松手后更快回到 HOME |
| Maximum tilt | 60° | 允许更大的最大角度 |
| Speed for max tilt | 6 H/s | 需要更快横移才达到最大目标角度 |
| Tilt response | 40 | 更快进入新倾角 |
| Straighten speed | 65 | 停住或松手后更快恢复角度 |
| Rotation damping | 1 | 当前为临界阻尼，降低才允许振荡 |

面板上限分别扩展为跟随 120、回位 100、倾斜与回正响应 120、最大倾角 85°。想进一步贴手，可以将 Follow speed 调到 70–90；希望只有更猛烈的甩动才大幅倾斜，可以将 Speed for max tilt 调到 8–10。Play 中调参退出后会恢复，长期保留需在 Edit 模式的 Controller Inspector 修改并保存场景。

## 验证记录

验证环境：Unity 6000.6.0f1、URP 17.6.0、DX11。通过 Unity CLI 创建场景、编译、运行验证菜单并截图。菜单为 `TechArtLab > 003 > Validate and Capture`，需要 Play 模式。

验证使用隔离的 Controller，避免消耗实际场景的外部事件监听器。覆盖屏幕/平面坐标换算、内外命中、旋转后命中、当帧状态与事件顺序、重复按下/释放、边角抓取、停住回正、回位/原地停留、回位途中再次抓取、失焦与禁用释放。

固定轨迹比较 30、60、120 Hz，在每秒的共同采样点检查位置差异小于 0.03 世界单位、角度差异小于 1 度，并检查最大角度受限及最终稳定。截图包含原位、慢拖、左右快速折返、停住、释放后和回到原位。

实际结果保存在本地 `References/003_BalatroCardDrag/analysis/unity/validation.txt`，截图同目录。当前原作动画的精确速度、按下时 hover 消退、回弹来源和系统鼠标端到端手感仍需对照；自动验证覆盖输入路由调用与运动计算，未声称已匹配原作。

2026-09-20 初版检查时，旧预设在 30/60/120 Hz 的最大倾角约为 33.170°、33.254°、33.254°。同日根据手感反馈拆分调参后重新验证，当前报告与截图对应新预设：上述行为检查通过，30/60/120 Hz 的每秒共同采样点差异小于报告显示精度 0.00001 世界单位和 0.0001 度；固定轨迹最大倾角均约 18.425°，因为这条轨迹速度不足以触及新的 60° 上限。旋转阻尼比 0.6 时仍能观察到有限回弹，默认 1.0。

新增调参验证采用 120 Hz、居中抓取、卡高 3.2 世界单位，检查结果为：

- 最大角度 60°、饱和速度 6 H/s、Follow speed 55：鼠标匀速 1 H/s 持续 1 秒后，实际倾角约 9.83°；鼠标正反向 7 H/s 时实际倾角分别达到 -60°、60°。鼠标 6 H/s 时卡片弹簧速度约 5.896 H/s，所以不能把二者直接等同。
- 饱和速度提高到 12 H/s，同样鼠标 6 H/s 持续 1 秒，实际倾角约 29.48°。
- 关闭倾斜、目标跳变 1 世界单位，0.1 秒后 Follow speed 为 22、55 的中心剩余距离分别为 0.3546、0.0266 世界单位。
- 固定 Follow speed 120、最大角度 60°、饱和速度 6 H/s，先以鼠标 6 H/s 匀速 1 秒，再停住 0.15 秒：Straighten speed 为 12、65 的剩余倾角约 29.35°、0.14°；直接释放并保持释放中心时约为 25.57°、0.03°。

最终编译和重跑验证通过，无新增运行错误或警告，面板截图已检查。首次新增测试曾把鼠标 6 H/s 当作卡片 6 H/s，断言失败；诊断确认是弹簧速度与输入速度的区别，修正饱和条件后通过，未将该失败描述为原作证据。

同日新增抓取位置回归验证：中心、四边中点和四个角附近共 9 个位置（局部坐标 X/Y 为 -0.45、0、0.45），分别在 30/60/120 Hz 下输入相同相对位移，逐帧比较位置、目标中心、速度、实际倾角、目标倾角和交互状态。覆盖直立开始、倾斜回位途中重新抓取，以及释放回家、停在释放中心两种模式。旧版在该测试中出现状态时序差异；修复后全部通过，最大位置/目标差异约 0.000001 世界单位，速度差异约 0.000022 世界单位/秒，角度差异约 0.000092°。按下瞬间的位置与角度保持不变，原有跟随与回正测试也通过。证据仍为 `References/003_BalatroCardDrag/analysis/unity/validation.txt`。
